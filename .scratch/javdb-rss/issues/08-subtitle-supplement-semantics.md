## Question

需求原文：「参数控制只返回第一个种子链接（追新），如果出现了有中文字幕的链接，
则也返回第一个有中文字幕的（补充中文字幕的）」。

同一个番号因此会有**两条 item**（普通第一条 + 中文字幕第一条）。
剩下的语义要用户拍板：

1. **两条 item 的关系**：中文字幕那条是
   - (a) **独立新增**一条（qBittorrent 会**两个都下**），还是
   - (b) **替换**掉原来那条（qB 只会保留一条）？
   用户原话「补充」偏向 (a)。要跟用户确认：字幕版出现后，是第一版**继续留着**
   （可能已经下过、会占空间），还是需要人工/规则去重？
2. **`guid` 怎么构造**，才能让 qBittorrent 正确区分这两条、且同一部作品不会重复下载？
   候选：
   - `infohash`（最干净 —— 磁链自带，内容变了 guid 就变）
   - `番号 + ":" + 槽位 + ":" + infohash`（`abc-123:first:<hash>` / `abc-123:zh:<hash>`）
   要确认 qBittorrent 的 RSS 去重是按 guid 还是按 enclosure URL。
3. **标题怎么写**，让用户在 qBittorrent 的 RSS 列表里一眼分得清哪条是字幕版。
   候选：`[ABC-123] 中文字幕 · <原磁链显示名>`。要不要把体积/做种数也带上？
4. **中文字幕的判定口径**（依赖 ticket 06 的结论）：
   - 优先用 App API 的显式字段
   - 没有的话，用磁链显示名 `dn` 的关键词解析。这时关键词表怎么定？
     「字幕」「中字」「中文」「CH」「-C」「C」…… 误判的代价是什么
     （下到一部没字幕的片 vs 漏掉一部有字幕的）？用户更怕哪个？
5. **只有字幕版、没有普通版**时怎么办？（只发一条，还是也发一条占位）
6. **`pubDate` 取什么**：发布时间还是我们第一次看到它的时间？影响 qB 的排序。
