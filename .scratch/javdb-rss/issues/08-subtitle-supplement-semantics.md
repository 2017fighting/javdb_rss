## Question

需求原文：「参数控制只返回第一个种子链接（追新），如果出现了有中文字幕的链接，
则也返回第一个有中文字幕的（补充中文字幕的）」。

同一个番号因此会有**两条 item**（普通第一条 + 中文字幕第一条）。
剩下的语义要用户拍板：

1. **两条 item 的关系**：中文字幕那条是
   - (a) **独立新增**一条（qBittorrent 会**两个都下**），还是
   - (b) **替换**掉原来那条（qB 只会保留一条）？
   用户原话「补充」偏向 (a)。要跟用户确认：字幕版出现后，是第一版**继续留着**
   （可能已经下过、会占空间），还是需要人工/规则去重？
2. **`guid` 怎么构造**，才能让 qBittorrent 正确区分这两条、且同一部作品不会重复下载？
   候选：
   - `infohash`（最干净 —— 磁链自带，内容变了 guid 就变）
   - `番号 + ":" + 槽位 + ":" + infohash`（`abc-123:first:<hash>` / `abc-123:zh:<hash>`）
   要确认 qBittorrent 的 RSS 去重是按 guid 还是按 enclosure URL。
3. **标题怎么写**，让用户在 qBittorrent 的 RSS 列表里一眼分得清哪条是字幕版。
   候选：`[ABC-123] 中文字幕 · <原磁链显示名>`。要不要把体积/做种数也带上？
4. **中文字幕的判定口径**（依赖 ticket 06 的结论）：
   - 优先用 App API 的显式字段
   - 没有的话，用磁链显示名 `dn` 的关键词解析。这时关键词表怎么定？
     「字幕」「中字」「中文」「CH」「-C」「C」…… 误判的代价是什么
     （下到一部没字幕的片 vs 漏掉一部有字幕的）？用户更怕哪个？
5. **只有字幕版、没有普通版**时怎么办？（只发一条，还是也发一条占位）
6. **`pubDate` 取什么**：发布时间还是我们第一次看到它的时间？影响 qB 的排序。

## Answer

**已定（2026-09-28 与用户面对面 grill 得出）**

### 1. 槽位规则：字幕优先，每部作品恒为 1 条

```
若 magnets 中存在 cnsub == true → 取第一条 cnsub == true 的
否则                          → 取 magnets[0]
```

**用户主动收窄了原始需求**。需求原文是「则**也**返回第一个有中文字幕的（补充中文字幕的）」，
即默认两条；grill 时用户改选**只发一条、字幕优先**。

### 2. `guid` = 纯 infohash（磁链 `hash` 字段，btih）

```xml
<guid isPermaLink="false">0e8f4789bdcab713effc3a07d1309a776c867b3e</guid>
```

理由：内容相同 = guid 相同 → 同一部片即使同时出现在番号订阅和女优订阅里，
qBittorrent 也只下一次；洗版（新 infohash）自动重新下载；且 guid 完全由内容决定，
**与「无状态」完全契合，重启不会变**。番号写在 `title` 里，可读性不受损。

### 3. 标题

- 字幕版：`[KV-328] 中文字幕 · <基名>`
- 普通版：`[KV-328] <基名>`

**基名的选择已被 ticket 03 修订**（实测发现）：原定「基名 = 磁链显示名」，
但 App API 返回的磁链 `name` 通常就是番号本身，会渲染成 `[KV-328] 中文字幕 · KV-328`。
改为：

```
作品标题 → 磁链 name → infohash
（依次退化，保证不产出空标题）
```

### 4. `pubDate` = 磁链的 `created_at`；解析失败时退化为「本服务首次见到它的时间」

（注意：退化路径会让 pubDate 随重启变化，但这不影响 guid，因此不影响去重。）

### 5. 已知后果（需写进 README，不在地图内解决）

无字幕版先下、字幕版后到时，**磁盘上会留两份** —— qBittorrent 不会自动删旧版。
清理旧版属于 qBittorrent 的职责，已列入 map 的 **Out of scope**。

### 6. 作废的子问题

- 原 Q4（中文字幕判定口径）：作废 —— 服务端直接给磁链级 `cnsub`。
- 原 Q5（只有字幕版没有普通版）：不存在了 —— 字幕优先，恒发一条。
- 原 Q1 的「两条 item 的关系」：不存在了 —— 只发一条。
