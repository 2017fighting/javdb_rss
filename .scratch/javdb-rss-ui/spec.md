# Spec — 订阅链接生成器（把已批准的设计稿 promote 成服务自己的页面）

**Status:** ready-for-agent
**Effort:** `.scratch/javdb-rss-ui/`（设计稿、ui-contract、证据、笔记都在这里）
**取代:** `.scratch/javdb-rss-followups/issues/06-collected-bulk-picking.md` 的验收清单
**设计权威:** [`ui-contract.md`](ui-contract.md)（令牌 + 11 条硬规则）；本 spec 不得与它冲突

---

## Problem Statement

我在 App 里收藏了 144 位女优（其中 6 位是男优），还建了几份清单。要订阅其中几位，
现在唯一的路是：手工读 `/collected` 的 JSON，把 id 抄下来，再自己拼
`/rss/actress/{id}.xml?since=…&filter_by_tags=…`。

拼错的代价不是报错，是**静默给错东西**：

- `filter_by` 掩码多写一段，年份会被上游悄悄丢掉；
- `filter_by_tags` 只对女优实体生效，在第 6 个 id 上被静默丢弃；
- 月份/时长的 id 与真标签 id 撞号，喂错通道会筛出另一批作品；
- 标签超过 5 个、有时长没年份，上游都不吭声。

也就是说：我不知道哪些参数是真的、哪些是「看着筛了、其实没筛」。设计稿（可点 mockup +
`ui-contract.md` + 40 项行为断言）已经把这件事设计完了，但它是**静态页面 + 冻结数据**：
144 位女优是一次快照、标签词表根本没接、页面也不在服务里，打不开也算不出我真实的清单。

## Solution

服务自己把那张页面端出来。打开 `http://<服务地址>/` 就是订阅链接生成器：挑女优、挑标签、
挑清单，底部「待复制」随时备着一串能直接粘进 qBittorrent 的 feed URL。

页面是**服务的一个端点**，不是另起一个前端工程：资产内嵌进单二进制（构建与运行都不需要
Node），数据来自服务自己的发现端点 —— 所以我看到的永远是我真实的收藏、清单与上游当前的
标签词表。为此补两个只读发现端点（标签词表、单个女优自己的标签），除此之外**不引入任何
服务端状态**：选了什么、待复制里有什么，只活在页面里，与「URL 即订阅、无状态」一致。

## User Stories

### 挑女优

1. 作为用户，我想在一个页面上直接看到我收藏的女优，这样我不必去读 `/collected` 的 JSON。
2. 作为用户，我想默认只看女优（138 位），并能切到「全部演员」（144 位）—— 因为我的收藏里确实有 6 位男优。
3. 作为用户，我想看到男优被标出来，这样切到全部演员时我知道多出来的是谁。
4. 作为用户，我想按名字或 id 搜索这 144 条，这样我不用翻页找。
5. 作为用户，我想勾选任意几位、每人一条链接，这样一次就把该订的都订上。
6. 作为用户，我想逐行选择「追新（`since=今天`）」或「全量（`pages=20`）」，并有一个默认模式一次覆盖所有行，这样我不用一行一行改。
7. 作为用户，我想逐行复制，也想一次复制全部。
8. 作为用户，我想有一个常驻的「待复制」输出台，别处不再放第二份 URL 列表 —— 两处同一份列表就是重复。
9. 作为用户，我想在页面上改服务地址（默认就是打开页面的那个源），而且改一次所有链接当场跟上 —— 因为 qBittorrent 可能在另一台机器上。
10. 作为用户，我想这个服务地址被记住，刷新后不用重填。
11. 作为用户，我想在没有配 token 时看到「读不到收藏，需要 token_file」这样指向下一步动作的话，而不是一个空列表。
12. 作为用户，我想在没配 token 时仍然能用手输 id 的方式做女优标签订阅 —— 标签筛选本身是匿名的，不该被收藏读不到连坐。
13. 作为用户，我想在收藏列表被翻页上限截断时看到「这份清单**已知不完整**」，而不是一份长得像完整的清单。

### 挑标签

14. 作为用户，我想看到女优自己的标签落到上游分组上（分组名、顺序、组内标签原样来自上游）。
15. 作为用户，我想 id 撞号时按名字消歧，对不上就不显示 —— 宁缺勿错。
16. 作为用户，我想基本组（主属性）只列出**这位女优支持的**那几个（她自己的 `filter_tags`），而不是词表里全部 6 个。
17. 作为用户，我想在选了另一位女优时才去取她的标签，并看到加载态。
18. 作为用户，我想标签上限是 5（上游硬限制），触顶时没选中的点不动，并且在旁边说明为什么点不动。
19. 作为用户，我想年份是**精确的整年**，选项文字不带「起」—— 一个看起来像区间、实际是精确值的筛选器是最典型的静默错误。
20. 作为用户，我想选了年份时「追新」自动让位，并说明原因（`since` 是本地下界、`year` 是上游整年，同时发必然是空 feed）。
21. 作为用户，我想在「全站标签」模式下能选年份、月份、时长，而在「某位女优的标签」模式下这三样被禁用并说明原因。
22. 作为用户，我想在全站模式下看得见、改得动片库（写错片库不报错、只会给另一个库的作品，所以它不能藏在 URL 里）。
23. 作为用户，我想全站模式下 `m`（含磁鏈）总是并进主属性 —— 不发它时上游返回的作品全都没有磁链，会得到一条看着坏了的空 feed。
24. 作为用户，我想切换模式时只属于另一模式的控件状态被清掉 —— 留下「界面上选着、链接里没有」是最坏的不一致。
25. 作为用户，我想标签与主属性按**词表顺序**拼进 URL，这样同样的选择永远得到逐字符相同的链接，我能直接比对两条链接是不是一回事。
26. 作为用户，我想页面上关于「全站标签做不成」「年份只有下界」这类**已被证伪的旧结论**被改掉，而不是留在那里误导下一个人。

### 清单与想看

27. 作为用户，我想清单区一清单一链接（5 份真实清单），并标出哪份是默认清单、哪份是私有。
28. 作为用户，我想「想看」有一个单独、显眼的复制按钮。
29. 作为用户，我想一份清单如果不是公开的，页面说清它的名字可能读不到、链接仍然可用（退回 id 当标题）。

### 拿到的链接必须是对的

30. 作为用户，我想拿到的链接里只有语义参数（`since` / `pages` / `main` / `tags` / `year` / `month` / `duration`），掩码由服务构造 —— 段数那些坑不该有两处实现。
31. 作为用户，我想拿不到的链接就不给：会 503 或 404 的（没 token 的「想看」/「清单」、没放行的片库）按钮禁用并说明缺什么，绝不给我一条点了就坏的链接。
32. 作为用户，我想在白名单生效时被告知，这样我不会奇怪为什么某条链接一订就 404。
33. 作为用户，我想复制在局域网 http（非安全上下文）下也能用。
34. 作为用户，我想复制后有一个「已复制 ✓」的反馈，并被读屏播报。
35. 作为用户，我想在页面上看到上游是否正常（服务已有的 `/readyz`）。

### 能用、能读、能部署

36. 作为用户，我想用键盘走完全部流程：焦点可见、分段控件能方向键切、折叠的标签组能展开。
37. 作为用户，我想深色模式跟随系统，也能手动覆盖。
38. 作为用户，我想空态与错误态各自说清下一步动作，而不是一句「失败」。
39. 作为用户，我想页面在没有任何外网/CDN 的情况下也能用（资产内嵌）。
40. 作为用户，我想这个页面不需要新增配置项，Dockerfile 与 k8s 清单也不用改。
41. 作为用户，我想读端点在没有 token 时也能用（标签词表、女优标签都是匿名可读的）。

## Implementation Decisions

### 页面

- 新增一个「页面」模块（Go 包）用 `embed` 持有全部前端资产，由 `httpapi` 挂在服务根路径上。
  构建与运行都**不需要 Node**：Tailwind 产物（CSS）入库，与 `.scratch/javdb-rss-ui/shots/`
  入库同一套理由 —— 评审与构建都不该先装一遍工具链。
- **路由锚定**：页面只注册在精确的 `GET /{$}`（Go 1.22+ 的根锚点），资产走 `GET /assets/` 前缀。
  不能用 `GET /` 当通配 —— 那会把 `/rss/want` 这类打错的 feed 路径喂成 HTML 页面，
  而 qBittorrent 只会报「这不是一个 feed」。打错的 feed 仍必须是干净的 404。
- 资产同源、无 CDN、无第三方字体或脚本。页面不做鉴权、不引会话 —— 与「本服务不做鉴权、
  默认只监听 loopback」一致。页面**不新增数据暴露**：它只是把已有/新增的只读端点组织起来。
- 前端只发**语义参数**，永不发 `filter_by` / `filter_by_tags`（契约硬规则 8：掩码由服务构造）。
  「待复制」里存的是选择（kind + 女优 id / 模式 / 主属性 / 标签 / 年份 / 月份 / 时长 / 片库），
  每条 URL 在渲染时派生 —— 换服务地址、跨过零点都当场跟上。
- 服务地址默认取 `location.origin`（页面由服务自己提供时那就是对的），可改并持久化。
  只有 UI 偏好（服务地址、主题）进 `localStorage`；选择与待复制只活在内存里 ——
  刷新即空，免得留下一批来路不明的旧链接。
- 排序确定性：主属性按词表 `main` 组顺序，标签按分组顺序 + id。同样的选择 ⇒ 逐字符相同的 URL。
- 无 token 时的行为：`/collected` 与 `/collected_lists` 已经会 503，页面照实显示它的文案；
  同时把「想看」「清单」的输出禁用并说明（它们读的是 App 里的标记，没 token 一定 503），
  标签区保持可用（词表与女优标签匿名可读），女优 id 可以手输。
- 折叠状态、搜索、模式切换等交互不变量 1:1 复现 `ui-contract.md` 第「这个页面的交互不变量」一节
  （11 条硬规则全部照做，含复制回退链、1.8s 反馈、`aria-live`、`prefers-reduced-motion`）。

### 两个新的只读发现端点

沿既有家族约定：发现端点在 `/rss/` 之外、不带 `.xml`、返回 JSON（`/collected`、`/collected_lists` 就是这一族）。

- **标签词表** `GET /tags?type={片库号}`
  - 上游 `GET /api/v2/tags?type={zone}` 的透传 + 归一。`type` 只接受 0–3，其余 **400**：
    上游对非法值是**静默回落**（`type=9` 与 `type=0` 响应逐字节相同），
    照原样透传就等于把「另一个片库的词表」当成你要的答案给出去，而那是本项目最不能接受的一类失败。
  - 响应形状：`{"groups":[{"category_id":…,"category":…,"tags":[{"id","name","videos_count"}]}]}`。
    顶层用 `groups`（避免「`tags` 里装的是分组」的歧义），组内字段名沿用上游，
    与 `/collected` 沿用 `videos_count`、`/collected_lists` 沿用 `movies_count` 是同一套做法。
    **分组顺序、组内顺序、分组名、标签名一律原样**（契约硬规则：分组不是我们编的）。
  - **不需要 token**（匿名可读）。
  - 片库白名单 `feeds.zones` 生效：没放行的片库返回 404「未知的订阅」，
    与 `/rss/tags/{zone}.xml` 同一套语义 —— 这样页面不会渲染一个订不到的片库。
- **某位女优自己的标签** `GET /actress_tags/{id}`
  - 上游 `GET /api/v1/actors/{id}` 的一次读取，返回 `{id, name, videos_count, main, tags}`。
  - `main` 来自上游顶层 `filter_tags`（`[{id,name}]`，如 EvkJ 的 `p s m c`），
    刻意不叫 `filter_tags`：它是 feed URL 里 `main=` 的取值集合，而叫 `filter_tags`
    会让人以为里面是标签。
  - `tags` 来自上游顶层 `tags[]`（`{id,name,videos_count}`），**上游不给分组**，分组由页面按词表反查。
  - **不需要 token**；女优白名单 `feeds.actresses` 生效（同上，404 而不是 403）。
  - 现有的 `ActressName` 打的是同一个上游端点：合并成一次读取，一个实现三个字段，
    免得「名字」与「标签」两份 envelope 各漂各的。
- **`/version` 增白名单状态**（三类各一个布尔）：页面据此在「白名单生效」时给一句提示。
  没有这个字段，白名单就会表现为「链接看得见、一订就 404」—— 正是契约硬规则 6 要避免的那类静默。

### 数据来源

- `catalog.Source` 增两个方法：`TagVocabulary(ctx, zone)` 与 `ActressTags(ctx, id)`。
  - `appapi` 实现按上面的上游路径。
  - `stub` 实现提供**结构性、可缩写**的 fixture：分组 id/名字与上游一致（0/1/2/3 各一套、组数不同），
    标签列表可以短。理由：stub 是给离线与浏览器套件用的，而把 130KB 的上游数据塞进二进制不值得。
  - 因此浏览器套件里「144 位 / 307 个标签 / 5 份清单」这类**条数**断言改用 fixture 的数；
    断言的价值在结构与逐字符的 URL，不在数量。

### 文档

- `CONTEXT.md` 的 Language 节增补两条术语：**标签词表**（上游按片库给出的分组与标签，
  分组名与顺序原样使用）、**订阅链接生成器**（页面；把「我要订什么」变成一串 URL，本身不存状态）。
- `README.md` 增一节「打开页面」：怎么打开、它需要什么（无 token 时哪些区可用）。
- `ui-contract.md` 继续是唯一的设计权威。promote 里**改了行为**的地方要作为新的硬规则写回它
  （按女优 `filter_tags` 列基本组、手输 id、无 token 时禁用输出、截断信号可见），
  而不是只活在代码里 —— 这是设计循环的 LEARN 一步。

## Testing Decisions

**什么算好测试**：只测外部行为 —— HTTP 状态码与响应体、页面**产出的 URL 逐字符**、
页面在某个状态下的文案与可用性。不测内部函数名、不测实现结构。

### 接缝 1（新）：`httpapi` handler 层

`httptest` + `internal/stub` 当 Source。先例：`internal/httpapi/collected_test.go`、
`lists_test.go`、`browse_test.go`、`want_test.go`、`server_test.go`。

要断言的外部行为：

- `GET /tags?type=0`：分组顺序与名字原样；`type=9` / `type=` / `type=abc` → 400；
  没配 token 时仍然 200（匿名可读）；上游出错 → 502。
- `GET /actress_tags/{id}`：`name` / `main` / `tags` 三个字段齐；上游出错 → 502；
  白名单未放行的 id → 404。
- `GET /`：200 + `text/html`；`GET /assets/…` 200；**`GET /rss/want`（打错的 feed 路径）→ 404**
  （根锚点的回归守卫，别让它退化成 HTML）。
- `/collected` 形状**不变**的回归守卫：`gender` 仍在、`truncated`/`pages_fetched`/`max_pages`
  仍是「仅在触顶时出现」、`feed` 路径仍可访问。
- `/version` 新增的三个布尔存在。

### 接缝 2（改造现有）：把 `tools/flows.mjs` 指向真服务

现在它打的是静态 mockup（`mockup/src/data.js` 的冻结数据）。改成打
`http://127.0.0.1:8080` 上一个 `provider=stub` 的真服务 —— 于是那 40 项断言守的不再是设计稿，
而是**上线的东西**；mockup 目录降级为设计记录（连同 `shots/` 一起保留）。

保留并更新原有断言（URL 逐字符、上限 5、折叠、键盘、复制回退、空态/无 token 文案），并新增：

- 待复制里的每条 URL **都不含** `filter_by` / `filter_by_tags`（掩码只由服务拼）。
- 女优模式下基本组只列该女优 `filter_tags` 里的字母。
- 手输一个不在 `/collected` 里的女优 id 仍然能出标签与链接（没 token 也能用）。
- `type=2` 的词表与 `type=0` 不同（证明词表是按片库取的，不是写死快照）。
- `/collected` 报截断时，列表上出现「已知不完整」。
- 无 token 状态下「想看」「清单」的输出被禁用且有说明。

跑法：`verify.sh` 一条命令（构建 CSS 不需要了 —— 产物入库；但要先起服务）。
浏览器套件**不进 CI**（CI 没有 node/浏览器，与现状一致）；CI 仍然只有 gofmt / vet / race / build / docker build。

### 不做

- 不在 Go 侧再实现一遍 URL 构造。前端那处是**唯一**实现，所以它只在接缝 2 里被验 ——
  这正是契约硬规则 8 的目的：掩码语法只有一处。
- 不为掩码语法写第二份测试（服务的掩码构造已有 `internal/appapi` 与 `internal/httpapi` 的测试覆盖）。

### 人验（照需求 1/2/3 的先例）

用真上游 + 真 token 跑一次：打开页面 → 生成一条（含标签与年份）→ 粘进真实 qBittorrent →
确认条目能出来。这一步进了 README 的验收记录。

## Out of Scope

- **女优掩码尾部**（女优模式的月份/时长）—— 还没抓包验出来，页面照旧禁用并说明。
- 上游根本没有的通道：`until=`、独立 `duration=`、`month=` 单独生效等。
- 服务端保存选择、会话、鉴权、多用户。
- 页面的配置开关（它总是开着）；Dockerfile / k8s 清单的改动。
- **清单白名单开不开**（设计稿 README 第 3 条，用户待定）—— 本票不替他决定；页面只负责在
  白名单生效时说出来。
- 「加入待复制」的主次（设计稿 README 第 5 条，仍开放）—— 本票保持现状（复制为主、加入为次）。
- 删掉 mockup / tools / notes：它们是这次 promote 的设计记录与证据，保留。
- PWA / 离线 / 多语言（文案只有 zh-CN）、把浏览器套件搬进 CI。
