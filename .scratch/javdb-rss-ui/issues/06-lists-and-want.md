# 06: 清单区 + 想看区

**Spec:** [`../spec.md`](../spec.md)

**What to build:** 清单区一清单一链接（标出哪份是默认清单、哪份是私有），「想看」一个单独的复制按钮；两者都能复制，也都能加入待复制。

没配 token 时这两个区的输出**禁用并说明原因** —— 它们读的是 App 里的标记，没 token 一定 503。给一条点了就坏的链接比灰掉更坏。

- [x] 清单与想看都能加入待复制，待复制里仍然只有一份 URL

## Comments

已实现，**没有动服务端代码** —— 清单发现端点（`/collected_lists`）与两条 feed
（`/rss/list/{id}.xml`、`/rss/want.xml`）在前面的票里就已就位，本票只把它们接到页面上。
页面侧在 `internal/webui/index.html`（新增 `#panel-lists` 与 `#panel-want`）与
`internal/webui/assets/app.js`，断言在 `tools/flows.mjs`（124 → 152 项）与
`tools/a11y.mjs`（清单卡片与它们在待复制里的行也进 axe）。Tailwind 产物逐字节没变
（用到的 utility 都已在产物里）。

几处值得记下的取舍：

- **「没 token」没有发现端点，只能从两个 503 推。** `/collected` 与 `/collected_lists`
  读的是同一份 App 标记，所以 `tokenMissing()` 取两者任一为 503。两个区因此**同时**
  被挡下，而标签区照旧可用（词表与女优标签匿名可读）—— 这正是需求 41 的分工。
- **拿不到就不给链接，而不只是把按钮灰掉。** `#want-url` 在「没有 token」与
  「token 状态还没定」两个态里都**不填 URL**（填的是说明），因为一条能手拷走的
  地址与一个能点的按钮一样坏。清单区在 503 下没有卡片，所以也没有可点的输出，
  只有一段写明 `token_file` 的服务原话。
- **清单 URL 用服务给的 `feed` 路径，不自己拼。** `/collected_lists` 已经把
  `/rss/list/{id}.xml` 交出来了（自己拼错了只会得 404，而用户会以为服务坏了）；
  页面只把服务地址前缀接上去，所以换服务地址那条链接仍会当场跟上。
- **“私有”分两种写法都要说清：**有名字的私有清单说「名字可能读不到，feed 标题会
  退回 id」；名字本身为空的（不分公私）说「上游没给出名字，标题退回 id」。
  私有优先：它恰好解释了名字为什么会读不到。链接两种情况都给 —— 订阅本身是好的。
- **待复制里一条 kind 只留一条。** 同一份清单重复点「加入待复制」是同一条链的
  新版本（替换而不是堆叠），「想看」是一条固定路径因此只可能有一条；待复制仍然
  只有 `state.links` 这一份清单，每条 URL 在渲染时由 `linkUrl` 现算。
- **顺手把女优空态/错误态的重试按钮从 `btn-primary` 降成 `btn-outline`。**
  「想看」的复制按钮是内容区的主操作（契约：内容区最多一个 `btn-primary`），
  留着两个会在「收藏读不到」时同屏出现两颗主操作。这是为了不违反既有硬规则，
  不是为了改女优区 —— 落在提交说明里。

代码评审（standards + spec 两轴，并行 fresh 子代理）的结果与处置：

    改成「清单」。

    `/collected`，名字也没说清它在等什么）。

    以及 `linkUrl` / `renderTray` 各自按 `link.kind` 分支。四条 kind 的 URL 与 badge
    确实不同，抽一个策略表换来的是闭包与间接层；这与票 04/05 对同类判断项的处置一致。

  - 另一条是私有清单名字为空时只说了「上游没给出名字」、漏说「私有」—— 已让
    私有分支优先。
