# 04: 女优标签区

**Spec:** [`../spec.md`](../spec.md)

**What to build:** 「某位女优的标签」模式：选一位女优（或直接手输 id）→ 取她自己的标签 → 按词表反查落到上游分组上。基本组只列**她支持的**那几个主属性；标签上限 5，触顶时未选中的点不动并说明这是上游硬限制；分组可折叠、可搜索；年份是**精确的整年**（选项文字不带「起」），选了年份就让「追新」让位并说明原因。

没有 token 时这一区照旧可用 —— 标签词表与女优标签都是匿名可读的，不该被「收藏读不到」连坐。

**Blocked by:** 01, 02, 03

**Status:** resolved

- [x] 分组名与分组顺序原样来自词表；组内标签来自她自己的 `tags[]`
- [x] id 撞号时按**名字**消歧（月份 1–12 与真标签 id 全撞号）；对不上就不显示 —— 宁缺勿错
- [x] 基本组只列她的 `filter_tags` 字母，不是词表里全部 6 个
- [x] 标签上限 5：第 6 个点不动（并说明是上游限制）；触顶有解释文字；每组带已选计数
- [x] 分组默认折叠，可搜索（搜索时全展开）、可全部展开；「有已选」的组默认展开
- [x] 年份是整年、选项文字不带「起」；选了年份 `since` 让位且页面上说明为什么
- [x] 标签与主属性按**词表顺序**拼进 URL：同样的选择永远得到逐字符相同的链接
- [x] 切人时去取她的标签并有加载态；取不到要有说法，不能永远显示「?」
- [x] 手输一个不在收藏列表里的 id 仍然能出标签与链接
- [x] 生成的订阅 URL 里只有语义参数（`main` / `tags` / `year` / `since` / `pages`），没有 `filter_by`
- [x] `tools/flows.mjs` 新增对应断言并通过

## Comments

已实现。页面侧在 `internal/webui/index.html` 与 `internal/webui/assets/app.js`
（新增 `<section id="panel-tags">` 与标签区的那一组渲染/事件），断言在
`tools/flows.mjs`（40 → 76 项）与 `tools/a11y.mjs`。

这一区打的是两个**已经存在**的匿名发现端点（票 01 / 02）：`/tags?type=0` 取词表、
`/actress_tags/{id}` 取她自己的 `tags[]` 与 `filter_tags`。本票**没有新增服务端代码**
——两个端点的形状就是照这一屏的需要定的。

几处值得记下的取舍：

- **两处 id 撞号的分工不同。** 「她的标签 → 分组」按**名字**消歧（月份 1–12 与真标签 id
  全撞号），对不上就丢（`locateTag`）；而基本组的字母来自她自己的 `filter_tags`，
  **不经反查** —— 它本来就不在标签 id 空间里。丢失的后果不对称：标签丢了是少筛一条
  （看得见），把月份 id 当标签发出去是静默筛出另一批作品（看不见）。
- **基本组按词表 `main` 组顺序排，不是她的 `filter_tags` 顺序。** 她的上游顺序是
  `p s m c`，词表是 `p m c s`；URL 里的 `main=` 按后者拼（ui-contract 第 3 条），
  所以 chip 也用后者 —— 页面上的阅读顺序与链接里的参数顺序逐字对应。词表里没有的
  字母（上游万一新增）接在她自己的顺序后面，宁可多列也不藏。
- **标签按「组顺序 + id」排，页面上也一样。** chip 的渲染顺序就是 URL 的顺序，
  所以「看着是同一份选择」与「链接逐字符相同」是同一件事，不用自己心算。
- **折叠状态只记用户真点过的那些。** 一开始用 `<details>` 的 `toggle` 事件记状态，
  但**程序化设 `open` 也会触发它** —— 搜索时的「全展开」因此被记成用户的选择，
  清掉搜索后那些组再也折不回去。改成只认 `summary` 上的真实点击（键盘的
  Enter/Space 也会产生 click，所以键盘用户照样算数）。
- **`commitPicker` 会跳过同一个人。** 回车提交后输入框失焦会**再**发一次 `change`，
  那次重复请求会把已经渲染好的标签区打回加载态（用户看得见一闪）。上一次失败的要
  允许重试，所以只在成功/进行中时跳过。
- **「加入待复制」是按女优各留一条快照。** 同一位再点一次是同一条链的新版本（替换），
  换一位女优再加则是**并存**的 —— 挑完 A 再挑 B，A 那条还在。待复制仍然只有一份
  URL 列表：`state.links` 里存的是「怎么生成」，URL 每次现算。
- **`tools/flows.mjs` 里加了一个 `collapseTray()` 助手。** 待复制面板是固定在视口
  底部的浮层，展开时会盖住页面下缘 —— 想再点页面底部的「加入待复制」得先收起它。
  这是浮层的固有代价（ui-contract 要求它是常驻输出台），不是页面 bug。

代码评审（standards + spec 两轴，并行 fresh 子代理）的结果与处置：

- spec 轴：11 条清单**全部落实**，没有缺项、没有越界（票 05/06/07 的全站模式、清单/想看、
  状态可见性都没有提前做）。
- standards 轴提了一条硬违规与一条注释/行为不一致，都已修：
  - `#tag-search` 的 label 原本是 `sr-only`（靠 placeholder 当标签），违反 ui-contract
    的 `.field`「标签永远在字段上方且常驻」。已改成可见 label，搜索字段单独一行。
  - 「同一位女优只留一条标签链接」的注释与 `filter((l) => l.kind !== "tags")` 的行为
    不符（那会把**所有**女优的标签链接都换掉）。已改成按 id 作用域，并补了断言。
- 三条判断项**刻意保留**，理由记在这里而不是埋在代码里：
  - 「复制这条」留在内容区：不变量 1 禁的是**第二份 URL 列表**，不是一个当前链接的复制
    按钮；票 06 对「想看」要求的正是同一个形态。
  - 分区是**竖排**而不是 `.tab`：票 03 已定下这一屏不分页，`.tab` 壳子不在本票范围内
    （契约把 `.tab` 列为「本 effort 用到的组件」，但没要求这一屏必须用它）。
  - `linkUrl` / 待复制移除处按 `link.kind` 分支、以及 `renderTagUrl` 里与 `tagQueryPairs`
    同形的条件：只有两种 kind，且后者的重复是「把参数条件翻成人话」而不是第二处实现。
