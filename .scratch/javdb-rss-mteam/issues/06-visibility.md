# 06: 可见性 —— 判定状态与凭据失效看得见

**What to build:** `/metrics` 出判定状态与凭据失效；判定**停滞**看得见；
README 写清这个功能新引入的暴露面。

**Blocked by:** 02, 04.

**Status:** ready-for-agent

- [ ] `javdb_rss_mteam_*`：已判定 / 命中 / 待判定 / 上次判定时间 / 凭据失效
- [ ] 「**从未判定过**」与「判定过且为 0」**分得开**（照 `/metrics` 里 `checked` 那条既有判断：
      报一个 0 的时间戳等于说 1970 年判定过）
- [ ] **判定停滞**（连续若干轮没有推进）可见 —— 它是「看起来在工作、实际没在工作」的那类失败
- [ ] 日志只在状态**翻转**时打，不每轮刷屏（照 `health` 的做法）
- [ ] README 新增一节，必写四件事：
      - 怎么开（`MTEAM_API_KEY` / `mteam.api_key`）、怎么「重置」
      - **凭据的暴露面**：本服务端出的种子带着账号凭据，而本服务不做鉴权 ——
        谁能访问它，谁就能拿到它（比现状「能看到你的订阅内容」严重一档）
      - **密钥轮换的后果**：轮换 M-Team 密钥后，已发出的种子会全部失效，
        而本服务**看不见也修不了**；唯一出口是逐部「重置」，代价是重复下载
      - 回填是渐进的（限速 100 个/小时），标题里的「待定来源」计数会随时间下降
- [ ] `make check` 与 `make race` 全绿
